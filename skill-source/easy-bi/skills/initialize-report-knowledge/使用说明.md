# 初始化数据库知识库 Skill 使用说明

本文面向使用 Easy BI 的开发者和项目管理员，说明如何通过 Agent 或命令行完成 MySQL 知识库的初始化、人工调整与发布。

Agent 的强制执行规则以 [SKILL.md](SKILL.md) 为准；字段格式、分层算法和目录结构以 [知识库技术规范](references/知识库技术规范.md) 为准。

## 1. 使用前准备

- Node.js 24；
- 一个独立的 Easy BI 客户工作区；
- MySQL 地址、端口、用户名、密码或密码环境变量；
- 当前业务系统涉及的全部数据库名；
- 推荐使用只读数据库账号；
- 已规划报表时，准备报表名称和期望展示字段。

一个工作区代表一个客户业务系统，可以连接多个 MySQL 实例和多个数据库。

## 2. 推荐的 Agent 使用方式

将本 Skill 安装到工作区后，对 Codex、Claude Code 或 Innos Agent 使用下面的提示：

```text
请使用 initialize-report-knowledge Skill，在当前 Easy BI 工作区初始化数据库知识库。
先检查本地依赖，再引导我填写 MySQL 连接和数据库列表。
连接通过后，引导我在 config/easy-bi.json 中填写计划报表名称和所需字段。
生成热、温、冷分层计划后先让我确认，再构建知识库草稿。
只询问真正阻断发布的问题，不要逐表提问，也不要执行任何 DDL 或 DML。
```

Agent 应按以下顺序推进：

1. 检查依赖与运行环境；
2. 初始化或检查工作区；
3. 配置并测试所有数据库；
4. 配置计划报表需求；
5. 扫描数据库并生成热、温、冷计划；
6. 等待用户确认分层计划；
7. 构建可编辑草稿；
8. 批量完善枚举和必要语义；
9. 校验并发布知识库版本。

## 3. 最少需要填写的配置

配置文件固定为：

```text
<workspace>/config/easy-bi.json
```

数据库配置只需要包含连接基础信息和该连接下的全部数据库名。密码可以直接填写，也可以通过环境变量提供；不要把密码复制到知识库、日志或发布版本。

计划报表配置示例：

```json
{
  "id": "driver-basic-detail",
  "name": "司机基础信息明细",
  "required_fields": [
    { "field": "base_primary_driver.code", "label": "司机编码" },
    { "field": "base_primary_driver.name", "label": "司机姓名" },
    { "field": "base_primary_driver.phone", "label": "手机号" }
  ]
}
```

优先填写 `表名.字段名` 和中文列名。也可以先写中文业务字段，Skill 会在知识库中唯一匹配；存在多个候选时才会要求确认。

## 4. 命令行完整流程

以下命令均在本 Skill 目录执行。

### 4.1 检查依赖并初始化工作区

```bash
npm run bootstrap:core
node dist/scripts/catalog-cli.js doctor --scope knowledge
node dist/scripts/catalog-cli.js init-workspace \
  --root <workspace> \
  --system-id <system-id> \
  --system-name "<system-name>"
```

依赖脚本会先检查本地已安装版本，只有缺失或版本不匹配时才下载。

### 4.2 校验配置并测试数据库

```bash
node dist/scripts/catalog-cli.js validate-config \
  --scope knowledge \
  --config <workspace>/config/easy-bi.json

node dist/scripts/catalog-cli.js test-connections \
  --config <workspace>/config/easy-bi.json
```

### 4.3 扫描并生成分层计划

```bash
node dist/scripts/catalog-cli.js discover \
  --config <workspace>/config/easy-bi.json \
  --out <workspace>/knowledge/scans/<scan-id>/snapshot.json

node dist/scripts/catalog-cli.js propose \
  --snapshot <workspace>/knowledge/scans/<scan-id>/snapshot.json \
  --hints <workspace>/config/easy-bi.json \
  --out <workspace>/knowledge/scans/<scan-id>/catalog-plan.json
```

确认热、温、冷表后批准计划：

```bash
node dist/scripts/catalog-cli.js approve-plan \
  --plan <workspace>/knowledge/scans/<scan-id>/catalog-plan.json \
  --approved-by "<reviewer>" \
  --decision "<approval-summary>"
```

### 4.4 构建、校验并发布

```bash
node dist/scripts/catalog-cli.js build \
  --snapshot <workspace>/knowledge/scans/<scan-id>/snapshot.json \
  --plan <workspace>/knowledge/scans/<scan-id>/catalog-plan.json \
  --config <workspace>/config/easy-bi.json \
  --out <workspace>/knowledge/drafts/<draft-id>

node dist/scripts/catalog-cli.js validate \
  --catalog <workspace>/knowledge/drafts/<draft-id>

node dist/scripts/catalog-cli.js publish \
  --catalog <workspace>/knowledge/drafts/<draft-id> \
  --workspace <workspace> \
  --version <semver> \
  --published-by "<publisher>" \
  --decision "<publish-summary>"
```

发布前必须完成必要语义确认，并确保发布校验通过。已发布版本不可原地修改。

## 5. 枚举配置

草稿构建时会自动初始化热表和温表的枚举候选，不会覆盖人工填写的中文名称。

需要批量维护时：

```bash
npm run bootstrap:excel

node dist/scripts/catalog-cli.js enums-export \
  --catalog <draft> \
  --out <workspace>/work/枚举配置.xlsx
```

Excel 包含两个工作表：

- `枚举字段绑定`：指定某个数据库、表、字段使用哪个共享枚举名称；
- `枚举值映射`：每行配置一个“枚举名称 + 枚举code → 中文名称”。

导入前先预览：

```bash
node dist/scripts/catalog-cli.js enums-import \
  --catalog <draft> \
  --file <workspace>/work/枚举配置.xlsx \
  --dry-run
```

预览无误后去掉 `--dry-run` 正式写入草稿。

## 6. 主要输出

```text
knowledge/
├── scans/<scan-id>/       数据库扫描和分层计划
├── drafts/<draft-id>/     人工与 Agent 可编辑的知识库草稿
├── versions/<version>/    不可变发布版本
└── index.json             当前发布版本索引
```

知识库按 `数据库连接 / 数据库 / 表` 导航。热表保存完整字段语义，温表保存可能使用的字段信息，冷表只保存表级摘要。

## 7. 重新扫描与人工调整

- 重新扫描必须生成新的 `scan-id`，不得修改旧扫描；
- 人工语义只在草稿中编辑，重新扫描不得覆盖；
- 温表或冷表可以通过 `promote` 提升为热表；
- 枚举重新扫描只补充新 code，不覆盖已有中文名称；
- 配置、草稿和发布版本应始终保留在客户工作区，不写回 Skill 源目录。

## 8. 常见问题

- **连接失败**：先确认网络、账号权限和数据库名，再运行 `test-connections`。
- **无索引时间字段**：Skill 仍会执行限时的最近数据存在性查询；超时只记为未知，不会误判冷表。
- **计划报表字段找不到**：优先改为 `表名.字段名`；中文名多义时从候选列表中确认物理字段。
- **发布失败**：查看草稿下的 `reviews/blocking-issues.json`，只处理其中的阻断项后重新校验。
- **只想继续上次任务**：复用现有工作区和草稿目录，从失败的确定性命令继续，不要重新初始化工作区。
