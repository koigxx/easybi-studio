# 生成报表包 Skill 使用说明

本文面向使用 Easy BI 的开发者和项目管理员，说明如何从已确认的报表需求和知识库生成标准报表包，并通过共享 Runtime 测试同步或异步导出。

Agent 的强制执行规则以 [SKILL.md](SKILL.md) 为准；报表格式、SQL、JOIN、计算字段和 Runtime 约束以 [报表与 Runtime 技术规范](references/报表与Runtime技术规范.md) 为准。

## 1. 使用前准备

- Node.js 24；
- 已初始化的 Easy BI 客户工作区；
- 可用的知识库草稿或已发布知识库版本；
- `config/easy-bi.json` 中已有对应的 `knowledge.report_requirements`；
- 同步真实导出时，数据库连接可用；
- 异步导出时，已配置阿里云 OSS 和业务任务接口。

一个 Skill 服务所有报表。每个具体报表只生成自己的字段、参数、SQL、计算逻辑和知识库锁定信息，不复制公共 Runtime。

## 2. 推荐的 Agent 使用方式

对 Codex、Claude Code 或 Innos Agent 使用下面的提示：

```text
请使用 create-report-package Skill，根据当前工作区 config/easy-bi.json 中的报表需求
和已生成的知识库，为 <报表ID> 创建 v2 报表包。
先生成并展示报表计划；单表无阻断时直接让我确认。
多表 JOIN、聚合或计算字段只集中询问一次缺失的业务规则。
批准后生成并校验报表包，再通过共享 Runtime 完成一次同步 Excel 导出测试。
不要重复询问已经在报表需求和知识库中确认的字段。
```

Agent 应按以下顺序推进：

1. 检查依赖与工作区；
2. 读取报表需求和知识库；
3. 生成 v2 报表计划；
4. 仅处理 JOIN、聚合或计算逻辑等阻断项；
5. 等待用户批准计划；
6. 生成并校验报表包；
7. 查询报表列表与参数；
8. 完成同步真实导出测试；
9. 需要时配置并测试异步导出。

## 3. 命令行生成报表包

以下命令均在本 Skill 目录执行。

### 3.1 检查依赖

```bash
npm run bootstrap:core
node dist/scripts/report-package-cli.js doctor
```

依赖脚本会先检查本地版本，只有缺失或版本不匹配时才下载。

### 3.2 生成报表计划

```bash
node dist/scripts/report-package-cli.js inspect \
  --workspace <workspace> \
  --knowledge <knowledge-directory> \
  --report-id <report-id> \
  --out <workspace>/reports/plans/<report-id>.json
```

单表、普通字段报表通常会直接得到无阻断计划。默认排序为创建时间倒序并以 ID 倒序作为稳定次序；没有创建时间时按 ID 倒序。

### 3.3 配置多表或计算逻辑

只有计划存在 JOIN、聚合或计算字段阻断时，才准备配置文件并执行：

```bash
node dist/scripts/report-package-cli.js configure-plan \
  --plan <plan-file> \
  --configuration <join-and-calculation.json>
```

配置可以声明：

- `LEFT` 或 `INNER JOIN` 及关联字段；
- 普通列、SQL 表达式和代码计算字段；
- `GROUP BY` 与固定 `HAVING`；
- 逐行或分组 TypeScript Transform。
- `group_queries` 多实体独立聚合：每个指标查询可带知识库锁定的短
  `LEFT/INNER JOIN` 路径，按稳定维度 ID 合并；n:n 计数使用
  `COUNT(DISTINCT 实体主键)`；
- 非物理业务指标（如“订单量”）会在 inspect 中给出确定性 `field_id`，配置文件
  用相同 id 明确解析后即可解除该 blocker，不需要把底层 ID 冒充成报表字段。

请求中的筛选值始终使用参数绑定，不能拼接进 SQL。

### 3.4 批准、生成并校验

```bash
node dist/scripts/report-package-cli.js approve-plan \
  --plan <plan-file> \
  --reviewed-by "<reviewer>"

node dist/scripts/report-package-cli.js generate \
  --workspace <workspace> \
  --plan <plan-file>

node dist/scripts/report-package-cli.js validate \
  --package <workspace>/reports/packages/<report-id>/<version>
```

每次修改字段、SQL、参数或 Transform 后都要重新校验。已发布版本不可原地修改，应生成新版本。

## 4. 查询报表和参数

生成并写入索引后，共享 Runtime 立即提供统一能力：

```bash
node dist/scripts/runtime-cli.js list \
  --workspace <workspace>

node dist/scripts/runtime-cli.js parameters \
  --workspace <workspace> \
  --report-id <report-id>
```

参数结果包含字符串、枚举、时间和数字等类型及支持的匹配方式，前端可据此复用一套筛选组件。租户 ID 不作为可见筛选项，但接口允许通过上下文传入。

## 5. 同步导出测试

同步导出需要 Runtime 依赖：

```bash
npm run bootstrap:runtime
```

执行真实导出：

```bash
node dist/scripts/runtime-cli.js export \
  --workspace <workspace> \
  --report-id <report-id> \
  --filters-json '{}' \
  --context-json '{}' \
  --output <workspace>/outputs/files/<report-id>.xlsx
```

也可以使用 `--tenant-id <tenant-id>` 传递可选租户上下文。测试通过至少应确认：

- 实际连接 MySQL 并执行只读参数化查询；
- 筛选条件生效；
- Excel 可以打开；
- 表头与报表字段一致；
- 输出文件位于工作区 `outputs`；
- 空结果和边界值不会导致导出失败。

同步分支最长查询 10 分钟，单个 Excel 最多自动拆成 2 个 Sheet；每个 Sheet 最多 1,048,575 行数据。

## 6. 启动统一 HTTP 接口

```bash
node dist/scripts/runtime-cli.js serve \
  --workspace <workspace> \
  --host 127.0.0.1 \
  --port 39080
```

对外固定提供：

```text
GET  /api/v1/reports
GET  /api/v1/reports/{reportId}/parameters
POST /api/v1/exports
```

`POST /api/v1/exports` 通过 `executionMode` 选择分支：

- `sync`：HTTP 200 返回 Excel 文件流；
- `async`：HTTP 200 返回任务信息，后台生成 Excel、上传 OSS，并更新业务任务状态。

业务错误也统一返回 HTTP 200，通过响应体中的 `success=false` 和错误码判断。异步配置缺失时必须明确报错，不会自动切换为同步。

## 7. Runtime 配置

配置文件固定为：

```text
<workspace>/toolkit/config/runtime.json
```

同步测试不需要 OSS 或业务任务接口。异步导出必须配置：

- 阿里云 OSS Endpoint、Bucket、访问凭据和 URL 策略；
- 业务系统创建任务接口；
- 业务系统更新任务状态和文件地址接口；
- 必要的认证信息。

敏感配置只保存在客户工作区或运行环境中，不写入 Skill 快照、报表包或发布文档。

## 8. 主要输出

```text
reports/
├── plans/<report-id>.json
├── packages/<report-id>/<version>/
│   ├── report.manifest.json
│   ├── fields.json
│   ├── parameters.schema.json
│   ├── queries/
│   ├── transforms/
│   ├── tests/
│   ├── knowledge.lock.json
│   └── checksums.sha256
└── index.json
```

报表包只包含报表定制逻辑。数据库连接、Excel 生成、OSS、HTTP、队列和业务任务回调由共享 Runtime 统一处理。

## 9. 常见问题

- **FIELD_NOT_FOUND**：检查报表需求字段是否存在；优先使用 `表名.字段名`。
- **FIELD_AMBIGUOUS**：中文名或字段名命中多个候选，从提示中选择完整的 `数据库.表.字段`。
- **JOIN_REQUIRED**：使用 `configure-plan` 明确关联键、JOIN 类型和结果粒度。
- **计划无法批准**：先解决 `blockers`，不要手工绕过批准状态。
- **报表包校验失败**：重新生成校验和，并确认 SQL、字段、参数、Transform 和知识库锁定列一致。
- **同步导出失败**：先检查 Runtime 依赖、数据库连接、只读权限和筛选值格式。
- **异步导出失败**：检查 OSS 与业务任务配置；异步任务必须通过常驻 HTTP Server 执行。
- **旧 v1 报表包**：当前 Runtime 不读取也不迁移，删除旧索引和旧包后按 v2 流程重新生成。

## 10. 复杂报表与按需上下文

复杂报表先运行 `inspect`，再运行：

```bash
node dist/scripts/report-package-cli.js build-context --plan <plan> --out <workspace>/work/<report-id>-context.json
node dist/scripts/report-package-cli.js explain-plan --plan <plan>
```

AI 默认只读取生成的上下文切片；缺少某张关联表时，用 `--include database.table` 精确扩展。复杂报表按以下阶段执行，每个阶段使用全新 Agent 会话：

```bash
# 本次任务的隔离阶段根目录：<root>=<workspace>/work/report-build/<report-id>/<revision>
# 基础建模：产出字段/关系/口径草案，等待用户确认
node dist/scripts/report-package-cli.js init-model --plan <plan> --out <root>/discovery-model.json
node dist/scripts/report-package-cli.js build-phase-context --phase discovery --plan <plan> --out <discovery-context>
node dist/scripts/report-package-cli.js validate-stage --phase discovery --plan <plan> --root <root>

# 确定建模：只带草案与精确知识切片，产出可批准模型
node dist/scripts/report-package-cli.js build-phase-context --phase modeling --plan <plan> --model <discovery-model> --out <modeling-context>
node dist/scripts/report-package-cli.js validate-stage --phase modeling --plan <plan> --root <root>
# 用户点击批准后由 Studio 执行
node dist/scripts/report-package-cli.js approve-staged-model --plan <plan> --root <root> --reviewed-by <reviewer>

# 每条查询独立编译；默认单条最多 3 张表、40 个字段
node dist/scripts/report-package-cli.js build-phase-context --phase query --plan <plan> --model <report-model> --query-id <query-id> --out <query-context>

# 封装脚本只拿查询输出契约，不带物理知识库
node dist/scripts/report-package-cli.js build-phase-context --phase script --plan <plan> --model <report-model> --query-outputs <query-output-dir> --out <script-context>

# 脚本完成后由 Studio 确定性装配、批准、生成和静态校验
node dist/scripts/report-package-cli.js finalize-staged --workspace <workspace> --plan <plan> --root <root> --reviewed-by <reviewer>
```

阶段 Context Pack 自带允许/禁止输入、资源上限和预期输出。Studio 只有在 `validate-stage` 通过后才切换阶段；SQL/query-output 必须与批准模型的列名、顺序和类型一致。查询缺字段时停在当前阶段，不要把整份知识库和历史对话重新塞给脚本 Agent。需要多阶段处理时生成 v3 隔离脚本包，脚本只使用 `queryStream/loadIndex/batchLookup/emit`，资源预算同时受包声明和 Runtime 上限控制。

取消同步执行时，调用方应自行提供 `X-Request-Id`，然后请求 `DELETE /api/v1/executions/{requestId}`；异步任务使用 `DELETE /api/v1/tasks/{runtimeTaskId}`。
