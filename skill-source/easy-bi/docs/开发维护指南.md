# Easy BI 开发维护指南

## 1. 文档用途

本指南面向 Easy BI、Easy BI Studio、Skill 和 Runtime 的维护者。具体 Agent 执行流程以两个 `SKILL.md` 为准，目录和兼容约束以 `skills/目录与项目兼容性规范.md` 为准。

## 2. 正式目录

```text
Easy BI 源目录：
/Users/admin/innos/easy-bi-workspace/easy-bi

Easy BI Studio：
/Users/admin/innos/easy-bi-workspace/easybi-studio

外置客户工作区：
/Users/admin/innos/easy-bi-workspace/easybi-studio-workspaces/<workspace-id>

Studio Bundle 缓存：
~/.easybi-studio/skill-cache/easybi/<bundle-version>
```

正式 `easy-bi` 是 Bundle 的唯一来源。Studio `vendor/easybi-bundle` 是生成快照，客户工作区是独立安装副本；不得反向把快照或客户文件覆盖到正式源目录。

## 3. 技术基线

- Node.js 24 LTS；
- TypeScript；
- MySQL 只读连接；
- ExcelJS 流式工作簿；
- SQLite 异步任务队列；
- 阿里云 OSS；
- React/Vite Studio；
- Java/Vue 业务系统通过 HTTP 接入。

项目不依赖 Python。两个 Skill 的依赖由各自 `package.json` 和 `npm-shrinkwrap.json` 锁定。

## 4. 依赖规则

依赖准备必须先检查本地：

```bash
npm run bootstrap:core
npm run bootstrap:runtime
npm run bootstrap:excel
npm run bootstrap:dev
```

不同 Skill 只提供实际支持的命令。Bootstrap 必须：

1. 检查 `node_modules` 和精确锁定版本；
2. 已满足时不下载、不访问网络；
3. 仅缺失或版本不匹配时运行安装；
4. 知识库基础扫描不提前安装 Excel、OSS 或 Runtime 依赖。

## 5. 修改前检查

修改 Skill、Runtime、目录、JSON、CLI 或 API 前：

1. 阅读 `skills/目录与项目兼容性规范.md`；
2. 阅读目标 Skill 的 `SKILL.md` 和唯一技术规范；
3. 读取 `skills/bundle.manifest.json`；
4. 判断变更是内部实现、兼容扩展还是不兼容变更；
5. 全局查找路径、命令和格式版本的使用位置；
6. 确认不会覆盖人工语义、发布版本、配置或输出。

分类规则：

| 类型 | 示例 | 处理 |
|---|---|---|
| 内部实现 | 私有函数、查询优化、测试重构 | Skill 补丁版本，正常回归 |
| 兼容扩展 | 新增可选字段、命令或适配器 | 声明默认值，旧读取方可忽略 |
| 不兼容变更 | 改字段语义、CLI 参数、格式或 API | 提升主版本并提供明确处理方案 |

## 6. TypeScript 构建与测试

知识库 Skill：

```bash
cd skills/initialize-report-knowledge
npm test
```

报表与 Runtime Skill：

```bash
cd skills/create-report-package
npm test
```

修改 `scripts/*.ts` 后必须重新编译 `dist/`。源码、`.js`/`.mjs` 和测试必须一致。

Studio：

```bash
cd /Users/admin/innos/easy-bi-workspace/easybi-studio
pnpm test
pnpm lint
pnpm typecheck
pnpm build
```

最小回归范围：

- CLI 参数与全局版本解析；
- 知识库连接、扫描、冷热分层、枚举和发布；
- 单表、多表 JOIN、SQL 聚合、row/group Transform；
- 业务指标从 `FIELD_NOT_FOUND` 阻塞项转为显式计算字段，以及多指标实体/n:n 的 `group_queries` 独立锁定、JOIN 路径校验、去重聚合与合并容量上限；
- 参数化筛选、逻辑删除和租户上下文；
- Excel 两 Sheet 上限；
- Runtime 三个 HTTP 接口；
- 新工作区创建、Bundle 安装和哈希；
- 至少一个旧工作区的只读兼容检查。

## 7. Skill 维护

每个 Skill 只保留：

```text
SKILL.md
使用说明.md
agents/openai.yaml
references/<唯一技术规范>.md
assets/
scripts/
dist/
tests/
package.json
npm-shrinkwrap.json
tsconfig.json
```

`SKILL.md` 保存 Agent 核心工作流和执行门禁；`使用说明.md` 保存开发者与管理员的操作步骤；详细格式、判断政策和契约合并到唯一技术规范。不要再增加 README、安装说明、快速参考、临时清单、阶段总结或重复的接口文档。

修改后校验：

- Frontmatter 仅保留 `name` 和 `description`；
- `SKILL.md` 中所有链接存在；
- `使用说明.md` 的命令、输入和输出与当前 CLI 一致；
- `agents/openai.yaml` 与触发描述一致；
- CLI 示例与 Manifest 命令入口一致；
- Skill 单元测试通过。

## 8. Bundle 发布

任何 Skill、Runtime 或 Bundle 文件变化都必须：

1. 更新对应 Skill 版本；
2. 更新 `skills/bundle.manifest.json` 的 Bundle 版本和 Skill 版本；
3. 更新 `skills/index.json`；
4. 更新兼容范围；
5. 编译并测试；
6. 从正式源目录生成 Studio 快照；
7. 创建新的不可变缓存，不覆盖同版本缓存；
8. 校验 Manifest 中全部文件 SHA-256；
9. 运行 Studio 全量回归。

同步命令：

```bash
cd /Users/admin/innos/easy-bi-workspace/easybi-studio
node scripts/sync-easybi-bundle.mjs \
  --source /Users/admin/innos/easy-bi-workspace/easy-bi
```

同一版本内容发生变化时必须提升版本，不能删除缓存后复用版本号。

## 9. 工作区初始化与切换

平台打开工作区时：

1. 读取 `skills/bundle.lock.json`；
2. 根据锁定版本定位不可变缓存；
3. 校验 Bundle Manifest 和文件哈希；
4. 根据 Manifest 的逻辑路径读取配置、知识库、报表和输出；
5. 缺少非用户文件时可补齐；
6. 不覆盖现有数据库配置、Runtime 配置、草稿、发布版本和报表；
7. 运行依赖检查和 `doctor`；
8. 显示下一步。

切换工作区只切换根路径和 Bundle Lock，不切换代码分支，也不读取另一个工作区的数据。

新工作区使用当前 Bundle。旧工作区继续使用自己的安装版本，只有用户明确选择升级时才切换。

## 10. v2/v3 报表规则

当前支持：

```text
plan_format_version=2
report_package_format_version=2
report_package_format_version=3
```

格式 v1：

- CLI 不生成、不校验和不迁移；
- Runtime 列表、参数和导出均拒绝；
- 不创建 v1 备份；
- 工作区所有者明确删除索引条目、计划和包后重新生成 v2 或 v3。

Runtime HTTP `/api/v1/*` 保持不变，它是独立接口版本。

v2 保存声明式 SQL/JOIN、Transform、enrichment 和 `group_queries`。v3 保存独立知识锁的多条只读查询与受限脚本，只能通过 `queryStream/loadIndex/batchLookup/emit` 工作；数据库连接留在父 Runtime。生成前必须完成语义计划和执行计划审阅，并通过 `build-context` 按需加载知识。

## 11. 数据和安全

- MySQL 只允许元数据查询和参数化 `SELECT`；
- 禁止 DDL、DML、存储过程和把请求值拼入 SQL；
- Distinct 枚举扫描必须限时、限量，失败不阻断；
- 密码、OSS Key 和 Token 不进入知识库、报表包、Bundle、日志或前端回显；
- 报表输出只能写入当前工作区 `outputs` 或配置的 OSS；
- 已发布知识和报表版本不可原地修改；
- Studio 页面不能读取 Skill 私有源码。

## 12. Runtime 维护

共享 Runtime 由 `create-report-package` Skill 维护。具体报表包不得复制：

- HTTP Server；
- MySQL 连接与事务；
- Excel 写入；
- OSS Adapter；
- 业务任务回调；
- SQLite 队列；
- 统一错误和日志。

查询规则：

- MySQL 控制语句使用 `query()`；
- 业务 `SELECT` 参数化并流式读取；
- 最多两个 Sheet；
- 默认查询超时 600 秒；
- 同步测试必须真实生成并验证 Excel；
- 异步缺少 OSS 或任务接口时明确报错；
- v3 包级预算不得突破 Runtime 全局预算，取消必须中断查询并终止受限子进程；
- 复杂报表优先流式主查询、有限索引和分批查找，禁止把多个大事实表全部载入内存。

## 13. Studio 与 Innos 适配

Studio 和 Innos 通过统一适配层调用确定性 CLI：

```text
UI
  → Workspace/Skill Adapter
  → Bundle Manifest 命令与逻辑路径
  → Skill CLI / Runtime CLI
```

本地开发可使用 Claude Code 全权限模式，但权限范围仍限定在当前工作区。接入 Innos 时替换 AgentBridge，不改变 Skill、工作区和 Runtime 契约。

独立服务通过既有网关反向代理。业务系统只需消费 Runtime 三个接口，前端根据参数 Schema 复用筛选组件。

## 14. 文档维护

正式文档入口固定为：

- `docs/总体架构.md`；
- `docs/开发维护指南.md`；
- 两个 Skill 的 `SKILL.md`、`使用说明.md` 和唯一技术规范；
- `skills/目录与项目兼容性规范.md`；
- `toolkit/contracts/统一接口契约.md`。

当前处于开发阶段，不维护按日期累积的变更记录。新结论直接更新上述稳定文档、Manifest、Schema 和测试，不再新增按阶段、日期、问题或页面拆分的设计文档。临时分析应放在任务上下文或工作区 `work/`，完成后删除。

## 15. 交付清单

每次交付至少说明：

- 变更内容和兼容性分类；
- Bundle、Skill 和格式版本；
- 公共目录是否变化；
- 现有工作区是否需要操作；
- 单元测试、Studio 测试和真实导出结果；
- Bundle SHA-256；
- 未完成或需要业务接口补充的事项。
